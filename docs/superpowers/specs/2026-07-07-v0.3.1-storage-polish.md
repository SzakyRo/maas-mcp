# v0.3.1 Storage Polish — Design Spec

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Close 6 Minor findings deferred from the v0.3.0 final-review wave with surgical, test-driven changes — no new verbs, no behavior shifts visible to agents except one intentional raise-on-non-dict change.

**Architecture:** Extract the duplicated `(system_id non-empty AND id > 0)` validation from 15 storage verbs into a single `_validate_ids` helper colocated with `_storage_paths.py`. Surface schema drift in the two `get_*` verbs by raising `ValueError` instead of silently returning `{}`. Fill 12 test gaps that the per-task reviews flagged at v0.3.0 time, and add 2 new tests covering the schema-drift raise.

**Tech Stack:** Python 3.12+, FastMCP, Pydantic v2, respx (test mocking), pytest-asyncio, ruff, mypy --strict. Same stack as v0.3.0; no new dependencies.

## Background

The v0.3.0 final-review wave (commit `cad89b7`, tag `v0.3.0`) reported 0 Critical, 0 Important, 9 Minor findings. The 2 Important (README intro drift) were fixed in `cad89b7`. Of the 9 Minor, 6 are in scope here:

- **M1 / M5** (Tasks 22, 23): `if not system_id: raise ValueError` and `if id <= 0: raise ValueError` duplicated across 15 verbs. Candidate for a `_validate_ids` helper colocated with `_storage_paths.py`.
- **M2** (Task 22): `get_block_device` returns `{}` on a non-dict upstream response. Should surface schema drift loudly instead.
- **M3** (Task 23): `test_empty_system_id_raises_value_error` missing on `test_list_partitions.py` and `test_get_partition.py`.
- **M4** (Task 23): `test_bad_block_device_id_raises_value_error` missing on `test_get_partition.py`.
- **M6** (Task 24): `test_empty_system_id_with_confirm_true_still_fails` exists only on `create_block_device`. Should replicate across the other 9 destructive verbs so the "validate IDs BEFORE confirm" guarantee is tested symmetrically.

The remaining 3 Minor (unaccounted for in `progress.md` as individual items but reflected in the "9" count) are out of scope for v0.3.1: they either relate to the same root-cause findings covered here, or were observational notes ("consider this later") that don't justify a release.

## Global Constraints

These apply to every change in v0.3.1 unless explicitly overridden:

- **No new verbs.** v0.3.1 is a polish release; the curated surface stays at 31 verbs.
- **No CI/CD changes, no PyPI publish, no push.** Local-only, matching the v0.3.0 precedent and your standing instructions.
- **No new dependencies.** Same `pyproject.toml` as v0.3.0.
- **One file, one responsibility.** The helper goes in `_storage_paths.py` (next to the path templating it guards). It does NOT go in a new `_validation.py` module — that's YAGNI until validation needs to span non-storage curated verbs.
- **Preserve exact `ValueError` message wording.** Existing tests assert on substrings like `"system_id"`, `"block_device_id"`, `"partition_id"`. The helper's message format (`f"{name} must be > 0, got {value}"`) matches the existing per-ID format (`f"block_device_id must be > 0, got {block_device_id}"`) byte-for-byte once the caller passes the kwarg name. No test churn from the refactor itself.
- **Path-validation-before-confirm invariant.** Every destructive verb must raise on `system_id=""` even with `confirm=True`, before issuing any MAAS call. This is the property M6 protects.
- **`MCPUpstreamError` body-strip security fix (`5ad4a1a`) preserved.** Tests asserting on upstream errors continue to assert on the status code only (`"404" in str(exc_info.value)`), never on body text.
- **`Annotated[MaasClient, SkipJsonSchema()]` first-param pattern preserved** on every verb's `run` signature. No FastMCP JSON-schema regressions.
- **Local-only, v0.3.1 tag at post-review HEAD.** No push. Same convention as `v0.3.0` → `cad89b7`.

## Decisions

1. **`_validate_ids` signature uses `**ids: int` keyword-only.** This preserves existing exact error-message wording (`"block_device_id must be > 0, got {value}"`) without requiring per-call-site message formatting. Each verb passes its ID kwargs by name; the helper iterates and formats.

2. **Helper lives in `_storage_paths.py`, not a new module.** Single-purpose file with a 12-line addition. Colocated with the path templating that depends on it. Promoting to `_validation.py` later is trivial if non-storage verbs ever need the same rule.

3. **`get_*` verbs raise `ValueError` on non-dict response.** Specifically `get_block_device` and `get_partition`. List endpoints and `storage_summary` keep their existing shape-handling because their shapes genuinely vary across MAAS versions and need explicit fallbacks. Error message: `f"MAAS returned non-dict for <resource> <id> (got {type(resp).__name__}); schema drift?"` — specific enough to point at the right verb and id in logs.

4. **No README or docstring rewrites.** User-facing verb behavior is identical except for the raise-on-non-dict case (which is strictly safer). README's verb inventory and descriptions stay unchanged.

5. **Test gap scope:** M3+M4 add 3 tests (partition-read symmetry); M6 adds 9 tests (one per remaining destructive verb); M2 adds 2 tests (one per `get_*` verb, asserting the new raise). Total test additions: **+14** tests.

## Architecture

### `_validate_ids` helper

```python
# src/maasmcp/curated/_storage_paths.py (added at bottom)

def _validate_ids(system_id: str, **ids: int) -> None:
    """Validate MAAS path parameters used by storage verbs.

    system_id: MAAS node system_id (non-empty string).
    **ids: name → positive-integer pairs (e.g. block_device_id, partition_id).

    Raises ValueError on the first invalid argument. The error message for
    each id matches the verbatim format previously inlined in each verb so
    existing tests asserting on substrings (e.g. "block_device_id") keep
    passing without modification.
    """
    if not system_id:
        raise ValueError("system_id must be a non-empty string")
    for name, value in ids.items():
        if value <= 0:
            raise ValueError(f"{name} must be > 0, got {value}")
```

### Call-site refactors (15 verbs)

| Verb | Current validation | New call |
|---|---|---|
| `list_block_devices` | `if not system_id` | `_validate_ids(system_id)` |

| `list_partitions` | `system_id` + `block_device_id` | `_validate_ids(system_id, block_device_id=block_device_id)` |

| `storage_summary` | `system_id` | `_validate_ids(system_id)` |
| `create_block_device` | `system_id` + `name` (body field, not path) | `_validate_ids(system_id)` (name check stays inline) |
| `update_block_device` | `system_id` + `block_device_id` | `_validate_ids(system_id, block_device_id=block_device_id)` |

Validation order in destructive verbs is **path IDs first, then body-field checks, then confirm, then MAAS call.** This preserves the invariant M6 protects (path validation fires before `confirm`).

### Schema-drift raise (M2)

In `get_block_device.py` and `get_partition.py`, replace:

```python
return resp if isinstance(resp, dict) else {}
```

with:

```python
if not isinstance(resp, dict):
    raise ValueError(
        f"MAAS returned non-dict for {kind} {id_} "
        f"(got {type(resp).__name__}); schema drift?"
    )
return resp
```

`kind` and `id_` are interpolated with f-string literals per verb:
- `get_block_device`: `f"MAAS returned non-dict for block device {block_device_id} (got {type(resp).__name__}); schema drift?"`
- `get_partition`: `f"MAAS returned non-dict for partition {partition_id} (got {type(resp).__name__}); schema drift?"`

No existing test asserts on `{}` fallback, so no test churn from this change.

## Data Flow

Unchanged for reads and writes. The refactor is internal: the helper validates inputs identically to the inlined checks, then the verb proceeds with the same MAAS call. The only user-visible change is that `get_block_device` and `get_partition` now raise `ValueError` instead of returning `{}` on a non-dict response — strictly safer because schema drift becomes loud.

## Error Handling

Unchanged. The helper raises `ValueError` exactly as the inlined checks did. The schema-drift change adds a new `ValueError` path that previously returned `{}` silently — agents calling `get_block_device` / `get_partition` should already handle exceptions (FastMCP's error contract surfaces `ValueError` as a tool error).

async def test_empty_system_id_with_confirm_true_still_fails(

    """Path validation must happen BEFORE the confirm check."""
    with respx.mock(base_url=maas_client.base_url) as mock:

## Risks

- **Mypy `--strict` regression on the `**ids: int` signature.** Unlikely (PEP 448 since 3.5), but if it surfaces, fall back to a typed `int | None` per known kwarg. Mitigation: mypy is part of the per-task verification loop.
- **Test count drift in CI dashboards.** 149 → 163 is a +14 bump; anyone tracking the count by hand should update.
- **Behavior change on `get_*` verbs.** Agents that relied on `{}` fallback to indicate "not found" will now see an exception. Mitigation: MAAS 404 is already a `MCPUpstreamError(404)` via the security fix; agents should already handle exceptions. The new `ValueError` only fires on a 200 with a non-dict body, which is a real upstream bug.
