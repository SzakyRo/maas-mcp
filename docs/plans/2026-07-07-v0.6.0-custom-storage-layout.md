# v0.6.0 — Custom Storage Layout Composite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship one new curated verb `apply_storage_layout(system_id, layout, confirm)` that sequences leaf CRUD verbs to build multi-disk storage layouts (RAID 1 with `/boot/efi` off-array, RAID 0/5/6/10, plain partition tables), plus a README recipe section so agents can drive the leaf verbs directly. Surface goes 78 → 79.

**Architecture:** One new file `src/maasmcp/curated/apply_storage_layout.py` that owns (a) a pure-Python spec-validation function, (b) a sequential leaf executor (no `asyncio.gather` — storage writes have data dependencies), (c) a verify-after-each-step layer using existing `list_partitions` / `list_raids` calls, (d) partial-failure packaging that returns a dict (matches `network_layout` pattern; raises only on caller-error conditions). The verb instantiates existing leaf-verb classes (`CreatePartitionTool`, `FormatPartitionTool`, `MountPartitionTool`, `CreateRaidTool`, `FormatBlockDeviceTool`, `SetBootDiskTool`) the same way `deploy_machine.py` instantiates `WaitForStateTool`. No new MAAS endpoints, no new path helpers.

**Tech Stack:** Python 3.12+, FastMCP, Pydantic v2, respx (test mocking), pytest-asyncio, ruff, mypy --strict. Same stack as v0.3.0 / v0.3.1 / v0.4.0 / v0.5.0; no new dependencies.

## Global Constraints

These apply to every change in v0.6.0 unless explicitly overridden. Re-read before each task's review.

- **No new dependencies.** Same `pyproject.toml` as v0.5.0.
- **`_validate_ids` is the only validator.** Every new verb validates its path IDs through `_validate_ids(system_id, ...)` — never inline `if not system_id` / `if id <= 0` blocks. The function lives in `_storage_paths.py` and is reused.
- **`confirm: bool = False` on every destructive verb.** `apply_storage_layout` is destructive (mutates a machine's storage layout); it carries the standard `confirm` gate. Spec validation runs BEFORE the confirm check, preserving the v0.3.1 M6 invariant.
- **`Annotated[MaasClient, SkipJsonSchema()]` first-param pattern** on every verb's `run` signature.
- **MCPUpstreamError body-strip security fix (`5ad4a1a`) preserved.** Tests asserting on upstream errors continue to assert on the status code only, never on body text.
- **Schema-drift raise on non-dict upstream (M2).** Every step's `get_*` verification raises `ValueError("MAAS returned non-dict for ...; schema drift?")` instead of silently returning `{}` or the raw body.
- **`MaasClient.post()` / `.put()` signatures unchanged.** `async def post(self, path, *, json=None) -> Any`. Same kwarg name `json=` as v0.5.0.
- **MAAS authority.** The leaf verbs we call are already wired against the MAAS endpoints documented in `docs/reference/maasapi.md`. The composite does NOT introduce new MAAS endpoints; it only sequences existing leaf calls.
- **No `Annotated[..., SkipJsonSchema()]` for body fields.** Only the `client` parameter needs the annotation.
- **Local-only, no PyPI publish, no push.** Matches v0.3.0 / v0.3.1 / v0.4.0 / v0.5.0 precedent.
- **Flat layout under `src/maasmcp/curated/`.** `apply_storage_layout.py` goes directly into the existing flat directory (no subpackage). Matches v0.3.0 / v0.4.0 / v0.5.0 shape.
- **`v0.6.0` tag at post-review HEAD.** No push.

```python
"""apply_storage_layout: composite verb that sequences leaf CRUD to build
storage layouts (RAID with /boot/efi off-array, RAID without ESP, plain).

Sequential executor (no asyncio.gather — storage writes have data dependencies).
Verify-after-each-step via list_partitions / list_raids. Returns a partial-result
dict on mid-sequence failure (matches network_layout); raises only on caller-error
conditions (validation, confirm gate, NotImplementedError for reserved fields).
"""

from __future__ import annotations

from typing import Annotated, Any

from mcp.server.fastmcp import FastMCP
from pydantic.json_schema import SkipJsonSchema

from maasmcp.curated.create_partition import CreatePartitionTool
from maasmcp.curated.create_raid import CreateRaidTool
from maasmcp.curated.format_block_device import FormatBlockDeviceTool
from maasmcp.curated.format_partition import FormatPartitionTool
from maasmcp.curated.mount_partition import MountPartitionTool
from maasmcp.curated.set_boot_disk import SetBootDiskTool
from maasmcp.curated._storage_paths import _validate_ids, partitions_path, raids_path
from maasmcp.maas.client import MaasClient
from maasmcp.maas.errors import MCPUpstreamError


_SUPPORTED_LAYOUT_TYPES = frozenset({"raid_with_esp", "raid", "plain"})
_RAID_LEVELS = frozenset({0, 1, 5, 6, 10})


def _validate_spec(layout: Any) -> None:
    """Pre-flight spec validation. Raises ValueError on bad shape."""
    if not isinstance(layout, dict):
        raise ValueError("layout must be a dict")
    layout_type = layout.get("layout_type")
    if layout_type not in _SUPPORTED_LAYOUT_TYPES:
        raise ValueError(
            f"layout_type must be one of {sorted(_SUPPORTED_LAYOUT_TYPES)}, "
            f"got {layout_type!r}"
        )
    if layout.get("volume_group") is not None:
        raise NotImplementedError(
            "volume_group on top of RAID is reserved for v0.7.0; "
            "omit the field or set to null"
        )
    disks = layout.get("disks")
    if not isinstance(disks, list) or not disks:
        raise ValueError("layout.disks must be a non-empty list")
    boot_disk = layout.get("boot_disk")
    if not isinstance(boot_disk, dict):
        raise ValueError("layout.boot_disk must be a dict with block_device_id")
    boot_disk_id = boot_disk.get("block_device_id")
    if not isinstance(boot_disk_id, int) or boot_disk_id <= 0:
        raise ValueError(f"boot_disk.block_device_id must be > 0, got {boot_disk_id!r}")
    esp_seen = False
    root_seen = False
    for disk in disks:
        if not isinstance(disk, dict):
            raise ValueError("each entry in disks must be a dict")
        did = disk.get("block_device_id")
        if not isinstance(did, int) or did <= 0:
            raise ValueError(f"disk.block_device_id must be > 0, got {did!r}")
        parts = disk.get("partitions")
        if not isinstance(parts, list) or not parts:
            raise ValueError(f"disk {did}.partitions must be a non-empty list")
        for part in parts:
            if not isinstance(part, dict):
                raise ValueError(f"each partition must be a dict")
            size = part.get("size")
            if not isinstance(size, str) or not size:
                raise ValueError(f"partition size must be a non-empty string")
            if part.get("fstype") == "fat32" and part.get("mount_point") == "/boot/efi":
                esp_seen = True
    raid = layout.get("raid")
    if layout_type.startswith("raid"):
        if not isinstance(raid, dict):
            raise ValueError("layout.raid must be a dict for raid layouts")
        if raid.get("level") not in _RAID_LEVELS:
            raise ValueError(f"raid.level must be one of {sorted(_RAID_LEVELS)}")
        if raid.get("filesystem") and raid.get("mount_point") == "/":
            root_seen = True
    if not esp_seen:
        raise ValueError("layout must include one partition with fstype=fat32 and mount_point=/boot/efi")
    if not root_seen:
        raise ValueError("layout must mount root filesystem at / (raid.filesystem + mount_point='/' or a disk partition mount_point='/')")


def _summarize_spec(spec: dict[str, Any]) -> str:
    """One-line summary used in the confirm gate error message."""
    disk_count = len(spec.get("disks", []))
    raid = spec.get("raid") or {}
    return (
        f"layout_type={spec.get('layout_type')}, "
        f"disk_count={disk_count}, "
        f"raid_level={raid.get('level')}, "
        f"boot_disk={spec.get('boot_disk', {}).get('block_device_id')}"
    )


class ApplyStorageLayoutTool:
    name = "apply_storage_layout"
    description = (
        "Apply a custom storage layout to a MAAS machine by sequencing leaf "
        "CRUD verbs (create_partition, format_partition, mount_partition, "
        "create_raid, set_boot_disk). DESTRUCTIVE — pass confirm=True. "
        "Returns {status: 'complete' | 'partial', completed_steps, failed_step, "
        "errors, rollback_hint}. The RAID-with-ESP shape supports building "
        "RAID 1 with /boot/efi carved out on raw disks. MAAS must be configured "
        "with default_storage_layout=blank for this verb to leave storage "
        "configured as specified."
    )

    async def run(
        self,
        client: Annotated[MaasClient, SkipJsonSchema()],
        system_id: str,
        layout: dict[str, Any],
        confirm: bool = False,
    ) -> dict[str, Any]:
        _validate_ids(system_id)
        _validate_spec(layout)
        if confirm is not True:
            raise ValueError(
                "apply_storage_layout is destructive; pass confirm=True. "
                f"Affected: system_id={system_id}, spec={_summarize_spec(layout)}"
            )

        completed: list[dict[str, Any]] = []
        errors: list[str] = []

        def _record(step: str, **fields: Any) -> None:
            entry: dict[str, Any] = {"step": step}
            entry.update(fields)
            completed.append(entry)

        def _partial(failed: dict[str, Any], err: str) -> dict[str, Any]:            return {
                "system_id": system_id,
                "layout_type": layout.get("layout_type"),
                "status": "partial",
                "completed_steps": completed,
                "failed_step": failed,
                "errors": errors + [err],
                "rollback_hint": (
                    "To restore blank state, call op-restore_storage_configuration "
                    "on the machine (raw MAAS endpoint, not exposed as a curated "
                    "verb). Or call op-set_storage_layout with storage_layout=blank."
                ),
            }

        partition_ids: list[int] = []  # RAID-member partitions, by insertion order

        for disk in layout["disks"]:
            did = disk["block_device_id"]
            for part in disk["partitions"]:
                try:
                    resp = await CreatePartitionTool().run(
                        client,
                        system_id=system_id,
                        block_device_id=did,
                        size=part["size"],
                        partition_table_type="gpt",
                        confirm=True,
                    )
                except (MCPUpstreamError, ValueError) as exc:
                    return _partial(
                        {"step": "create_partition", "params": {"disk_id": did, "size": part["size"]}},
                        f"create_partition(disk={did}): {exc!r}",
                    )
                pid = resp.get("id") if isinstance(resp, dict) else None
                if not isinstance(pid, int):
                    return _partial(
                        {"step": "create_partition", "params": {"disk_id": did, "size": part["size"]}},
                        f"create_partition(disk={did}) returned non-dict or no id: {resp!r}",
                    )
                _record("create_partition", disk_id=did, partition_id=pid)
                listed = await client.get(partitions_path(system_id, did))
                if not isinstance(listed, list) or not any(
                    isinstance(p, dict) and p.get("id") == pid for p in listed
                ):
                    return _partial(
                        {"step": "verify_partition", "params": {"disk_id": did, "partition_id": pid}},
                        f"verify_partition(disk={did}, partition={pid}) failed; "
                        f"list_partitions did not return pid",
                    )
                if part.get("size") == "remaining":
                    partition_ids.append(pid)
                if part.get("fstype"):
                    try:
                        await FormatPartitionTool().run(
                            client,
                            system_id=system_id,
                            block_device_id=did,
                            partition_id=pid,
                            fstype=part["fstype"],
                            confirm=True,
                        )
                    except (MCPUpstreamError, ValueError) as exc:
                        return _partial(
                            {"step": "format_partition", "params": {"partition_id": pid, "fstype": part["fstype"]}},
                            f"format_partition(partition={pid}): {exc!r}",
                        )
                    _record("format_partition", partition_id=pid, fstype=part["fstype"])
                if part.get("mount_point"):
                    try:
                        await MountPartitionTool().run(
                            client,
                            system_id=system_id,
                            block_device_id=did,
                            partition_id=pid,
                            mount_point=part["mount_point"],
                            confirm=True,
                        )
                    except (MCPUpstreamError, ValueError) as exc:
                        return _partial(
                            {"step": "mount_partition", "params": {"partition_id": pid, "mount_point": part["mount_point"]}},
                            f"mount_partition(partition={pid}): {exc!r}",
                        )
                    _record("mount_partition", partition_id=pid, mount_point=part["mount_point"])

        if layout["layout_type"].startswith("raid"):
            raid = layout["raid"]
            try:
                raid_resp = await CreateRaidTool().run(
                    client,
                    system_id=system_id,
                    level=raid["level"],
                    name=raid.get("name"),
                    partitions=partition_ids,
                    confirm=True,
                )
            except (MCPUpstreamError, ValueError) as exc:
                return _partial(
                    {"step": "create_raid", "params": {"level": raid["level"]}},
                    f"create_raid(level={raid['level']}): {exc!r}",
                )
            raid_id = raid_resp.get("id") if isinstance(raid_resp, dict) else None
            if not isinstance(raid_id, int):
                return _partial(
                    {"step": "create_raid", "params": {"level": raid["level"]}},
                    f"create_raid returned non-dict or no id: {raid_resp!r}",
                )
            _record("create_raid", raid_id=raid_id, level=raid["level"])
            listed_raids = await client.get(raids_path(system_id))
            if not isinstance(listed_raids, list) or not any(
                isinstance(r, dict) and r.get("id") == raid_id for r in listed_raids
            ):
                return _partial(
                    {"step": "verify_raid", "params": {"raid_id": raid_id}},
                    f"verify_raid(raid_id={raid_id}) failed; list_raids did not return raid_id",
                )
            if raid.get("filesystem"):
                try:
                    await FormatBlockDeviceTool().run(
                        client,
                        system_id=system_id,
                        block_device_id=raid_id,
                        fstype=raid["filesystem"],
                        confirm=True,
                    )
                except (MCPUpstreamError, ValueError) as exc:
                    return _partial(
                        {"step": "format_raid", "params": {"raid_id": raid_id, "fstype": raid["filesystem"]}},
                        f"format_raid(raid_id={raid_id}): {exc!r}",
                    )
                _record("format_raid", raid_id=raid_id, fstype=raid["filesystem"])

        try:
            await SetBootDiskTool().run(
                client,
                system_id=system_id,
                block_device_id=layout["boot_disk"]["block_device_id"],
                confirm=True,
            )
        except (MCPUpstreamError, ValueError) as exc:
            return _partial(
                {"step": "set_boot_disk", "params": {"block_device_id": layout["boot_disk"]["block_device_id"]}},
                f"set_boot_disk: {exc!r}",
            )
        _record("set_boot_disk", block_device_id=layout["boot_disk"]["block_device_id"])

        return {
            "system_id": system_id,
            "layout_type": layout["layout_type"],
            "status": "complete",
            "completed_steps": completed,
            "failed_step": None,
            "errors": [],
            "rollback_hint": "",
        }

    def register(self, mcp: FastMCP) -> None:
        mcp.add_tool(self.run, name=self.name, description=self.description)
```

```markdown
**Custom storage layout:** `apply_storage_layout(system_id, layout, confirm)` sequences `create_partition`, `format_partition`, `mount_partition`, `create_raid`, and `set_boot_disk` from a single dict spec. Supports three layout types:

- `raid_with_esp` — partitions carved on each member disk, ESP (`fat32` mounted at `/boot/efi`) on raw disks, RAID over the remaining partitions, rootfs on RAID. Use this for RAID 1 with `/boot/efi` off-array.
- `raid` — partitions carved on each member disk, RAID over all of them. No ESP (BIOS boot only).
- `plain` — no RAID, one or more disks partitioned and optionally formatted + mounted.

Example: RAID 1 with `/boot/efi` off-array:

```python
apply_storage_layout(
    system_id="abc123",
    layout={
        "layout_type": "raid_with_esp",
        "disks": [
            {"block_device_id": 1, "partitions": [
                {"size": "1G", "fstype": "fat32", "mount_point": "/boot/efi"},
                {"size": "remaining"},
            ]},
            {"block_device_id": 2, "partitions": [
                {"size": "1G", "fstype": "fat32"},
                {"size": "remaining"},
            ]},
        ],
        "raid": {"level": 1, "name": "md0", "filesystem": "ext4", "mount_point": "/"},
        "boot_disk": {"block_device_id": 1},
    },
    confirm=True,
)
```

The verb returns `{status: "complete" | "partial", completed_steps, failed_step, errors, rollback_hint}`. On mid-sequence failure it returns a partial dict (no automatic rollback) so the agent can decide whether to retry, restore via `op-restore_storage_configuration` (raw MAAS endpoint, not a curated verb), or live with the partial state.

**Manual recipe** (driving leaf verbs directly, useful for incremental workflows): with MAAS cluster setting `default_storage_layout=blank`, call `create_partition` × N (each disk), `format_partition` × N (ESP and rootfs), `mount_partition` × N, `create_raid(level=1, partitions=[...])`, `format_block_device(raid_id, fstype)`, `set_boot_disk(block_device_id=...)`. Then `deploy_machine(system_id, distro="ubuntu/noble")` — MAAS will respect the existing layout because the cluster default is `blank`.

Requires MAAS cluster setting `default_storage_layout=blank` so MAAS does not re-layout storage on commission/deploy. If your MAAS uses a different default, MAAS will overwrite this work and the layout will not survive to deploy.
```

## Risks / non-obvious calls

1. **`partition_ids` selection.** The verb picks up `partition_ids` from partitions with `size="remaining"` — this is positional, not semantic. If a user writes `{"size": "5G", "fstype": None}` followed by `{"size": "remaining"}`, the second goes to RAID. If they write `{"size": "remaining"}` as the first partition, that also goes to RAID. The agent is responsible for declaring RAID members via the `"remaining"` sentinel.

2. **`list_partitions` may not be a list.** The MAAS endpoint returns either a bare list or a wrapped `{"partitions": [...]}` dict depending on version. The verb handles bare-list only via `isinstance(listed, list)` check — wrapped shape will fall through and verification fails with `verify_partition` step. If users hit this, add `_parse_list` helper (same pattern as `network_layout`). Out of scope for v0.6.0.

3. **`list_raids` similar ambiguity.** Same handling.

4. **GPT default may not match user's MAAS.** If MAAS is configured with a different default partition table type, the implicit `partition_table_type="gpt"` is still correct for UEFI but may surprise users on legacy systems. Documented in the verb description; agent can override via the raw `create_partition` leaf if needed.

5. **`set_boot_disk` on a raw disk.** The verb always sets the boot disk to `boot_disk.block_device_id` (a raw disk, never the RAID). This matches the "ESP off-array" requirement. If the user wants to boot from the RAID anyway (advanced), they can drive `set_boot_disk` separately after `apply_storage_layout`.

6. **`create_raid` member format.** The leaf verb accepts `partitions: list[int]` (MAAS partition IDs). The composite collects these from the `partition_ids` list, which is populated as partitions are created. This works for RAID-over-partitions but not for RAID-over-block-devices (a less common pattern) — that case is out of scope.

7. **No `volume_group` support.** The spec shape reserves the field, but the verb raises `NotImplementedError` if set. v0.7.0 will sequence `CreateVolumeGroupTool` and `CreateLogicalVolumeTool` after `create_raid`. The test `test_volume_group_raises_not_implemented` enforces this.

8. **`create_partition` with `partition_table_type="gpt"` is implicit.** MAAS has a default (MBR for older MAAS, GPT for newer). The verb forces GPT because UEFI requires it for `/boot/efi`. If the user wants MBR (legacy BIOS), they should use the raw leaf. Documented.

9. **Test fixture brittleness.** The `test_happy_path_raid_with_esp` and `test_sequencing_is_strictly_sequential` tests use respx route mocks with explicit per-route return values. If MAAS adds new required fields to responses, tests may need to add them. Mitigation: tests use minimal `{"id": N}` shapes; respx is a stable library.

10. **Sequential vs parallel test coverage.** `test_sequencing_is_strictly_sequential` checks call counts but not call ORDER. If a future implementer adds `asyncio.gather` that fires all create_partitions at once and they happen to succeed in order, the test passes but the verb is wrong. The test could be strengthened with strict-order mocking via `respx.route(side_effect=lambda req, state: ...)` and ordering assertions, but that adds significant complexity. v0.6.0 ships the lighter version; revisit if v0.7.0 touches this file.
